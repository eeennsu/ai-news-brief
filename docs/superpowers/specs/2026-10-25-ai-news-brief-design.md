# ai-news-brief 설계

작성일: 2026-10-25

## 목적

평일 아침, 한국장이 열리기 전에 밤사이 나온 AI 관련 뉴스 중 주가에 영향을 줄 만한 것을 한 번에 받아 본다. 용도는 두 가지다. 출근길에 흐름을 훑는 것, 그리고 보유·관심 종목에 영향이 있는지 확인하는 것이다. 사용자는 나 한 명이다. 매매 판단은 참고용이고 최종 결정은 사용자가 한다.

## 목표

- 한국장 개장일 평일 아침에 갤럭시 폰으로 푸시 알림이 온다. 기준은 8:15(KST) 전 도착이고, 8시 전에 오면 더 좋다. 생성이 끝나는 대로 바로 보낸다.
- 알림 본문에는 Top 2 뉴스가 한 줄씩 들어간다. 알림을 누르면 앱이 열리고 오늘 브리핑 전체(최대 10건)가 보인다.
- 앱에서 날짜별 지난 브리핑을 볼 수 있다.
- 뉴스 한 건에 들어가는 것:
  - 2~3줄 한국어 요약
  - 원문 링크, 발행 시각
  - 관련 종목(미국·한국). 종목마다 판정(호재·악재·중립), 강도(약·중·강), 근거 한 줄
  - 관련 종목 중 내 보유·관심 종목은 강조해서 보여 준다
- 보유·관심 종목은 레포의 설정 파일 하나에 적는다. 사용자가 Claude Code와 대화하면서 이 파일을 고친다.

## 뉴스 선별 기준

- 시장 관점: 밤사이 미국 뉴스를 중심으로 하고, 그 뉴스가 한국 관련주로 이어지는 영향까지 짚는다.
- 포함 범위: 상장사 주가에 닿는 경로가 있는 AI 뉴스.
  - 실적·가이던스(빅테크 capex 등)
  - 제품·모델·칩 발표
  - 규제·소송·수출 통제
  - 반도체·데이터센터 공급망(HBM, 전력 등)
  - M&A·투자 유치·IPO
  - 사고(데이터 유출, 대형 장애, 안전 사고)
- 제외: 연구 논문, SNS 화제성 데모·바이럴.
- Top 2 순서: 보유 종목에 걸린 뉴스를 먼저 올린다. 그런 뉴스가 없으면 시장 파급력 순으로 채운다. 3위 이하도 같은 기준으로 정렬한다.
- 건수: 최대 10건이다. 기준에 맞는 뉴스가 적은 날은 있는 만큼만 보낸다.
- 0건인 날: 빈 브리핑을 커밋하고 "오늘은 기준에 맞는 새 뉴스가 없다" 알림을 보낸다. 그러면 알림이 오지 않은 날은 곧 생성에 실패한 날이 된다.
- 안전장치(필수):
  - 원문 링크와 발행 시각을 확인하지 못한 뉴스는 넣지 않는다.
  - 직전 브리핑의 생성 시각 이후에 나온 뉴스만 넣는다. 직전 브리핑에 이미 실린 기사는 다시 넣지 않는다.
- 월요일 브리핑은 직전 브리핑(보통 금요일) 이후 주말 동안 나온 뉴스를 함께 다룬다. 위 "직전 브리핑 이후" 규칙을 따르면 자연히 그렇게 된다.

## 정해진 구성

### 전체 흐름

1. 평일 아침 7시 30분대에 Claude Code 예약 작업(Scheduled task)이 돈다. 모델은 Sonnet이다.
2. 예약 작업은 레포를 받아 지시문 파일을 따른다. 설정 파일(보유·관심 종목)과 직전 브리핑을 읽는다.
3. 웹 검색으로 뉴스를 모으고, 선별·요약·판정을 거쳐 오늘 브리핑 JSON을 만든다.
4. 브리핑 JSON을 레포 main에 커밋하고 push한다.
5. Expo Push Service로 폰에 알림을 보낸다. 본문은 Top 2다.
6. 앱은 알림을 누르면 열리고, 그날 브리핑을 GitHub에서 읽어 보여 준다.

  - 한국장 휴장일 목록 파일

### 생성: Claude Code 예약 작업

- 예약 작업 자체의 프롬프트에는 "레포의 지시문 파일을 따르라" 정도만 넣는다. 선별 기준을 바꿀 때는 레포의 지시문 파일을 Claude Code로 고친다.
- 시작 시각은 7시 30분대에서 정각을 피해 잡는다(예: 7:37). 공식 문서가 정각 예약은 몇 분 늦을 수 있다며 정각을 비켜 잡으라고 권하기 때문이다.
- 실행일은 평일이다. 그날이 휴장일 목록에 있으면 아무것도 하지 않고 끝낸다.
- 휴장일 목록은 1년에 한 번 Claude Code로 갱신한다.
- 비밀값(Expo 푸시 토큰, 그리고 Expo access token을 쓴다면 그것도)은 레포가 아니라 클라우드 환경의 환경 변수나 network secret에 둔다. 공개 레포에 푸시 토큰이 있으면 누구나 내 폰에 푸시를 보낼 수 있기 때문이다.
- 실패한 날은 알림이 오지 않는다. 재시도는 하지 않는다.
- 생성이 늦어지면 9:00 전까지는 보낸다. 9:00이 넘으면 브리핑만 커밋하고 알림은 보내지 않는다.

### 앱

- Expo, TypeScript, pnpm으로 만든다. 갤럭시(Android)에 APK로 직접 설치한다.
- 화면은 두 개다.
  - 오늘 브리핑: 알림을 누르면 여기로 온다
  - 날짜별 지난 브리핑
- 오늘 브리핑이 없으면 "오늘 브리핑 없음"을 띄우고, 가장 최근 브리핑으로 갈 수 있게 한다.
- 원문 링크는 외부 브라우저로 연다.
- 레포에 RN 플러그인을 켜고(`.claude/settings.json`의 `enabledPlugins`), CLAUDE.md에 `@~/my-agent-setup/docs/rn.md`를 넣는다. 코드를 쓰기 전에 conventions 스킬을 읽는다.

## 구현 첫 단계: 실행 방식 검증

예약 작업 관련 사실 중 아래는 공식 문서로 확인하지 못했다(2026-10-24 조사). 본 구현에 들어가기 전에 테스트용 예약 작업 하나를 만들어 "Run now"로 돌려 보고 확인한다.

| 확인할 것 | 문서 상태 |
| --- | --- |
| 클라우드 예약 작업에서 WebSearch가 동작하는가 | 미확인. WebSearch는 Anthropic 검색 백엔드를 쓴다고만 적혀 있다 |
| main에 직접 push되는가 | 프롬프트로 지정하면 된다고 적혀 있다. 동작은 확인이 필요하다 |
| `exp.host`로 POST가 나가는가 | 기본 Trusted 허용 목록에 있는지 미확인. Custom 네트워크나 network secret으로 열 수 있다 |
| 커스텀 cron의 타임존(UTC인지 로컬인지)과 월~금 지정 | 미확인 |
| 한 번 실행하는 데 걸리는 시간이 8:15 도착에 맞는가 | 실행 시간 상한 미확인. 실측한다 |

하나라도 안 되면 본 구현에 들어가지 않고 사용자에게 다시 묻는다. 대안은 GitHub Actions cron에 Claude API(웹 검색 도구)를 붙이는 방식이다. 이 경우 API 비용을 따로 내야 하고, 공식 문서에 부하가 클 때 예약 실행이 늦어지거나 누락될 수 있다고 적혀 있다.

## 참고한 외부 사실

확인일은 모두 2026-10-24다.

- Claude Code 예약 작업은 구독 사용량을 쓰고, 실행 주기는 최소 1시간이다. 모델을 고를 수 있다. 출처: https://code.claude.com/docs/en/routines
- Expo 푸시로 Android에 보내려면 FCM 설정이 필요하다(`google-services.json`, EAS에 FCM V1 자격 증명 등록). 발송 엔드포인트는 `https://exp.host/--/api/v2/push/send`다. 개발 빌드를 APK로 직접 설치한 경우에도 FCM 자격 증명이 필요한지는 미확인이다. 출처: https://docs.expo.dev/push-notifications/push-notifications-setup/ , https://docs.expo.dev/push-notifications/fcm-credentials/ , https://docs.expo.dev/push-notifications/sending-notifications/
- raw.githubusercontent.com의 캐시 시간은 공식 문서에서 찾지 못했다. 사용자 보고로는 약 5분이다.
